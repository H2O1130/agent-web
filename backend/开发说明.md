# 后端开发说明

启动一个服务即可：`semester-planning` 负责方案生成，`ai-chat` 负责对话调整，两者在同一进程里挂载路由；技能归并与课程映射仍是纯库。需求见顶层 [`需求与分工.md`](../需求与分工.md)。

## 结构

```text
backend/
├── 开发说明.md
├── skill_merger/            技能归并（纯库，无路由）
│   ├── README.md
│   ├── skills.json
│   ├── *.py                 服务、提示词、词表、类型、异常
│   └── tests/
├── course_mapping/          课程与实践映射（纯库，无路由）
│   ├── README.md
│   ├── requirements.txt
│   ├── requirements-dev.txt
│   ├── conftest.py
│   ├── app/                 catalog.json、提示词、校验、回填
│   └── tests/               pytest
├── semester-planning/        方案生成（/api/plan、/api/llm/*）
│   ├── README.md             接口、校验、DeepSeek 配置
│   ├── requirements.txt
│   ├── requirements-dev.txt
│   ├── .env.example
│   ├── app/                  FastAPI
│   └── tests/                pytest
└── ai-chat/                  对话调整（/api/chat）
    ├── README.md             边界、接口、错误码
    ├── ai_chat/              api、models、prompt、service
    ├── requirements-dev.txt
    ├── pytest.ini
    └── tests/                pytest
```

新模块沿用：模块根放 `README.md` + 依赖文件，测试进 `tests/`。服务模块的 Python 包用小写下划线名（`semester-planning/app`、`ai-chat/ai_chat`），避免同进程导入冲突；跨模块直接复用代码时由 `main.py` 把对方目录加入 `sys.path`。

## 运行

需要 Python 3.12+。

```sh
cd backend/semester-planning
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt -r requirements-dev.txt
uvicorn app.main:app --reload --port 8000
pytest                                  # 规划测试
cd ../ai-chat && pytest                 # 对话测试（复用同一套依赖）
```

`ai-chat` 不单独启动：`semester-planning/app/main.py` 会把 `backend/ai-chat` 加入 `sys.path` 并挂载 `/api/chat`。

macOS / Linux 用 `source .venv/bin/activate`。Windows 若 `python` 指向其他程序，改用 `py -3 -m venv .venv`，后续命令用 `.venv\Scripts\python.exe -m ...`。

## 约定

分支与合并流程见 [需求与分工.md](../需求与分工.md) 第 6.1 节：**合并进 `master` 只允许 `git merge --no-ff <分支>`**，不走 PR、不做快进。

- 请求/响应字段 camelCase，与 `frontend/src/types.ts` 一致。
- 错误统一 `{ code, message }`，`message` 为中文。
- 模型按学期输出任务 id、大致周数、理由与示例；静态字段后端回填。
- 校验失败或超时最多重试 2 次，仍失败直接报错，不回退本地引擎。
- 密钥只走环境变量；`.env` 不入库；日志不打印密钥。
