# 课程映射接入说明（兼容现有接口）

> 依据：`需求与分工.md`、`backend/开发说明.md` 与现有 `frontend/src/services/modelApi.ts` 的四个端点。本文件不是新契约，只说明课程映射如何在不改现有接口的前提下接进去。
> 一句话：**不新增端点、不改请求体、不改 `SkillStat`**；映射作为 `mappings` 字段并入 `/api/analyze` 响应，错误体沿用 `{code, message}`。

## 1. 现状（不改的部分）

| 项 | 现状 |
| --- | --- |
| 端点 | `POST /api/analyze` `{jobs} → {skills}`；`/api/plan`、`/api/plan/replan`、`/api/jobs/import` 不变 |
| 技能类型 | `SkillStat`：`id` 必填，`name` / `count` / `evidence` 可选 |
| 错误体 | `{code, message}`，前端只显示 `message` |
| 端口/代理 | 按现有配置，本模块不涉及 |
| 模型参数 | 90 秒超时、`temperature=0.2`、`max_tokens=16384`、关闭思考（原契约） |

## 2. 我们提供什么

| 名称 | 作用 | 位置 |
| --- | --- | --- |
| `CourseMapper(model_caller).map(skills, profile)` | 技能 → 课程 → 实践，返回 `MappingRow[]` | `app/service.py` |
| `analyze_payload(skills, rows)` | 把映射并入 analyze 响应 | `app/compat.py` |
| `error_response(error)` | 异常 → `(status, {code, message})` | `app/compat.py` |
| `rows_by_skill(rows)` | 按 `skillId` 建索引 | `app/compat.py` |

## 3. 接入（推荐，前端零改动）

```python
@app.post("/api/analyze")
def analyze(req):
    skills = merge_skills(req.jobs)          # 现有技能归并，11 项标准 id
    try:
        rows = mapper.map(skills, req.profile)
    except CourseMappingError as error:
        status, body = error_response(error)
        raise HTTPException(status_code=status, detail=body) from error
    return analyze_payload(skills, rows)
```

- `skills` 字段与顺序不变；旧前端忽略 `mappings` 也能跑，两端可分批上线。
- `mappings` 与 `skills` 等长、同序，一个技能一条。
- 课程/项目资料只在后端，请求里不要传课程数据。

## 4. 前端读取

- `skills` 不变；`mappings` 按 `skillId` join（`rows_by_skill`）。
- 后端未返回 `mappings`（旧版）时继续用 `data.ts` 的本地映射，不报错。
- 必须展示 `courseSource` / `projectSource` 与「示例」标识；`alreadyTaken` 为 true 时标「已修」。

## 5. 错误体兼容

| 异常 | code | HTTP | 说明 |
| --- | --- | --- | --- |
| `MappingInputError` | `bad_request` | 400 | 技能数组或画像字段不合法 |
| `ModelResponseError` | `llm_bad_response` | 502 | 模型输出两次不合格 |
| 其他 | `internal_error` | 500 | 未预期错误 |

调用方在 502 时按原契约重试 1 次；`map` 本身不重试、不缓存。

## 6. 模型调用方

- `callModel(prompt) -> str`（主约定）；返回已解析的 `{"mappings": [...]}` 也接受。
- 密钥只在服务端；不打印提示词与模型原文。
- 现有客户端若已经做了 `JSON.parse` 和重试，不需要为课程映射改动：把解析结果直接传进来即可，重试语义仍由调用方控制。

## 7. 尚未定的部分

- **端点由谁托管**：接口形状已经兼容，但一个进程只能调用一种语言的模块。现有 Node 入口若要调用本 Python 模块，需要子服务或重写；由 Python/FastAPI 托管则直接 import。这是唯一的结构性待定，不影响本文件的接口约定。
- **是否并入 `/api/plan`**：规划任务已有 `course` 字段；若规划也要用映射，可直接复用 `map` 的结果，不重复调模型。
- **真实培养方案**：替换 `catalog.json` 并放宽 `sourceKind` 后，本节其余不变。

## 8. 验收

- 11 项技能 → 11 条 `mappings`，顺序与 `skills` 一致。
- 空技能 → `mappings: []`，不报错。
- 非法模型输出 → 502 `llm_bad_response`，`message` 可读。
- 课程/项目来源可见且标「示例」。
