# 学途 PathPilot

学途是一个面向大学生的职业成长规划 Web 项目。学生选择目标岗位、填写当前基础和可投入时间后，可以查看岗位技能要求、课程与实践关联、分学期行动计划，以及条件变化前后的方案差异。

当前版本使用 Vue 3、TypeScript 和 Vite，提供可独立运行的前端演示。岗位分析与规划由本地规则完成。运行当前版本只需要 Node.js、npm 和浏览器，无需配置 Python、数据库、后端服务或大模型 API Key。

## 1. 最小运行环境

以下要求适用于安装依赖、开发和构建前端源代码。

| 项目 | 要求 |
| --- | --- |
| 操作系统 | 可运行兼容 Node.js 的 Windows、macOS 或 Linux |
| Node.js | 当前锁定的 Vite 7.3.7 要求 Node.js 20.x（至少 20.19.0），或 22.12.0 及以上版本；本次核验使用 22.x |
| npm | 随 Node.js 一起安装；项目提供 `package-lock.json`，使用 npm 安装依赖 |
| 浏览器 | 支持现代 JavaScript 的 Chrome、Edge、Firefox 或 Safari；自动化浏览器测试另需 Chrome |
| 网络 | 首次安装依赖时需要访问 npm 包源；当前演示运行时无需调用外部 API |
| Git | 下载和版本管理时使用，运行已下载的源代码不依赖 Git |

本次文档核验环境为 Windows、Node.js `22.20.0`、npm `10.9.3`。版本要求依据本项目的依赖锁定文件；npm 没有单独声明最低版本。

可从 [Node.js 官网](https://nodejs.org/)获取安装程序。安装后重新打开终端，检查：

```sh
node --version
npm --version
```

Windows PowerShell 如果提示无法运行 `npm.ps1`，使用 `npm.cmd`，例如 `npm.cmd --version`。本文中的其他 `npm` 指令也可对应替换成 `npm.cmd`。

## 2. 快速启动

在包含 `package.json` 的目录打开终端。当前工作区中的位置是：

```powershell
cd "D:\AAAA职业规划课\agent\agent-web"
```

如果项目下载到了其他位置，将路径换成实际目录。确认该目录同时包含 `package.json`、`package-lock.json`、`src/` 和 `index.html`。

首次运行：

```sh
npm ci
npm run dev
```

`npm ci` 按锁定文件安装依赖，适合首次运行和团队成员复现环境；它会重建现有 `node_modules`。日常启动且依赖没有变化时，只执行 `npm run dev` 即可。

启动后打开终端给出的地址，默认是 [http://127.0.0.1:5173/](http://127.0.0.1:5173/)。保持终端运行；在终端按 `Ctrl+C` 停止服务。修改源码后，开发服务器会自动更新页面。

需要固定端口时：

```sh
npm run dev -- --port 5173 --strictPort
```

`--strictPort` 会在端口被占用时明确报错；普通启动可能自动使用下一个可用端口。换用其他端口示例：

```sh
npm run dev -- --port 5174 --strictPort
```

## 3. 手机或同一局域网访问

默认服务只接受本机访问。需要用手机查看页面时，让手机和电脑连接同一网络，并运行：

```sh
npm run dev -- --host 0.0.0.0 --port 5173 --strictPort
```

在手机浏览器中打开终端显示的 Network 地址，例如 `http://192.168.1.10:5173/`。其中 IP 地址应替换为实际电脑地址。如果连接失败，检查设备是否在同一网络，以及系统防火墙是否允许该端口。

## 4. 常用指令

以下指令均在项目根目录，即包含 `package.json` 的目录执行。

| 指令 | 用途 | 前提 |
| --- | --- | --- |
| `npm ci` | 按锁定版本安装全部依赖 | 已安装 Node.js/npm，可访问包源 |
| `npm run dev` | 启动开发服务器 | 已安装依赖 |

| `npm run preview` | 本地预览生产构建 | 已成功执行构建 |

## 5. 构建与预览

```sh
npm run build
npm run preview
```

构建结果输出到项目内的 `dist/` 目录。预览服务默认地址为 [http://127.0.0.1:4173/](http://127.0.0.1:4173/)，以终端实际输出为准。需要指定端口时：

```sh
npm run preview -- --port 4173 --strictPort
```

修改源码后需要重新构建，预览服务才会展示新的构建结果。

部署时，将 `dist/` 内的文件交给静态网站托管服务或 HTTP 服务器。项目配置了相对资源路径 `base: './'` 和 Hash 路由，可部署到静态子目录。通过 HTTP 地址访问页面，不直接双击 `dist/index.html`。`npm run preview` 用于检查构建结果，正式部署使用静态托管服务。

仅访问部署后的网站时，学生只需要浏览器，无需安装 Node.js。

## 6. 测试方法

类型检查和规划逻辑测试：

```sh
npm run typecheck
npm test
```

端到端测试需要两个终端。先在终端一启动固定地址的开发服务，并保持运行：

```sh
npm run dev -- --port 5173 --strictPort
```

再在终端二进入同一个项目目录后运行：

```sh
npm run test:e2e
```

`playwright.config.ts` 当前指定 `channel: 'chrome'`，因此需要本机安装 Chrome。若要改用 Playwright 管理的 Chromium，需要先在该配置中移除 `channel: 'chrome'`，再执行 `npx playwright install chromium`。

单元测试覆盖岗位证据、去重、任务前置关系、时间预算、重规划和快照保护。端到端测试覆盖画像填写、岗位导入、路线生成、条件调整、历史记录、导出及响应式布局。失败截图和跟踪文件按测试配置输出到 `test-results/`。

## 7. 功能与体验流程

- 六步画像向导：填写专业、当前学期、目标岗位、已有基础、兴趣与每周课外时间。
- 岗位输入：从前端开发、Python 后端开发两个方向的 12 条教学样本中选择，或粘贴学生青睐岗位的原文。
- 岗位分析：按关键词、别名和分句规则识别技能，展示出现频次和原文证据。
- 课程与实践映射：查看技能对应的示例课程、项目和可检查成果。
- 分学期路线：依据前置条件、剩余学期和每周预算安排任务，无法安排的任务保留为待安排。
- 条件调整：修改时间、岗位或发展路径，查看新旧方案差异。
- 成果管理：查看历史方案、标记完成状态、导出 Markdown 计划。

建议的完整体验步骤：

1. 在首页选择“载入演示画像”。
2. 完成画像向导，选择岗位样本，或使用“导入岗位”粘贴招聘原文。
3. 查看技能分析、岗位证据和课程实践映射。
4. 生成分学期成长路线，检查任务成果与每周时间。
5. 进入调整页面，将每周时间由 12 小时改为 6 小时，查看任务保留和推迟情况。
6. 查看历史版本，或导出本次计划。

## 8. 当前实现与下一阶段设计

目标工作流为：

```text
招聘资料输入 → 要求提取 → 技能归并 → 课程与实践映射
           → 学生画像约束 → 分学期规划 → 条件变化后重规划
```

| 环节 | 当前实现 | 下一阶段设计 |
| --- | --- | --- |
| 招聘输入 | 教学样本 + 手动粘贴招聘原文 | 核验后的预置资料 + 学生当前计划内的临时岗位 |
| 要求提取 | 关键词、别名和分句规则 | 提取字段与原文定位，并保留人工复核 |
| 技能归并 | 本地规则归并、去重计数 | 大模型生成候选归并，程序计数并校验 |
| 课程与实践映射 | 本地示例映射 | 大模型依据真实课程和实践资料生成映射 |
| 学生画像约束 | 基础输入与预算规则 | 完善约束校验及课程开设信息 |
| 分学期规划 | 本地任务模板与排期规则 | 大模型生成规划，程序校验预算与前置关系 |
| 条件变化后重规划 | 规则重新排期并计算差异 | 复用模型规划能力生成新版，再计算差异 |

三个大模型接入点是技能归并、课程与实践映射、分学期规划；当前前端尚未调用大模型。接入时由服务端持有密钥并发起请求，前端展示经过校验的结果。

课程关联和每学期 16 周均为演示设定，需要按学校培养方案与教学日历校准。每周预算表示课外成长时间，自评表示学生本人对基础的认识。

### 数据保存规则

当前代码通过浏览器 `localStorage` 保存画像、导入岗位、计划历史和完成状态。数据属于当前浏览器与站点地址；不同端口或主机地址可能对应不同记录。清理站点数据会删除这些本地记录。

已确定的后续要求是：学生自导入岗位仅在当前计划的分析、生成和重规划过程中有效；退出计划、开始另一计划、刷新或关闭页面后清除。原文、链接、提取结果、证据及依赖它生成的方案版本均不进入持久存储或历史记录。预置岗位可跨计划复用。

**这项临时存储要求目前处于设计阶段，现有代码仍会保存导入岗位，尚需修改并验证。**

## 9. 项目结构

```text
agent-web/
├── public/                 静态资源
├── src/
│   ├── components/         共享界面组件、岗位选择与导入组件
│   ├── data/jobs.json      教学岗位样本
│   ├── views/              首页、向导、分析、路线、调整、历史页面
│   ├── App.vue             应用外壳
│   ├── main.ts             应用入口
│   ├── router.ts           Hash 路由
│   ├── store.ts            跨页状态与本地保存
│   ├── planning.ts         岗位分析、任务排期、方案差异
│   ├── planning.test.ts    规划逻辑单元测试
│   ├── data.ts             演示数据及技能、课程映射
│   ├── types.ts            业务类型
│   └── style.css           视觉样式与响应式布局
├── tests/                  端到端测试
├── index.html              HTML 入口
├── package.json            依赖声明与运行指令
├── package-lock.json       锁定依赖版本
├── tsconfig.json           TypeScript 配置
```

安装依赖后生成 `node_modules/`，构建后生成 `dist/`。这两个目录均已列入 `.gitignore`。

## 10. 常见问题

| 现象 | 处理方式 |
| --- | --- |
| 找不到 `node` 或 `npm` | 安装 Node.js 后重新打开终端，检查环境变量是否包含安装目录 |
| PowerShell 提示禁止运行 `npm.ps1` | 使用 `npm.cmd ci`、`npm.cmd run dev` 等对应指令 |
| 找不到 `package.json` | 进入本项目 `agent-web` 目录后再执行指令 |
| 提示 `EBADENGINE` 或 Node.js 版本不支持 | 用 `node --version` 检查版本，按上面的版本要求安装兼容环境 |
| 提示找不到 `vite` | 在项目根目录先执行 `npm ci` |
| `npm ci` 提示锁定文件不一致 | 同步同一版本的 `package.json` 和 `package-lock.json`；若是主动修改依赖，执行 `npm install` 更新锁定文件 |
| 安装依赖时网络失败 | 检查终端网络、代理和 npm 包源，恢复连接后重新执行 `npm ci` |
| 5173 端口被占用 | 停止占用该端口的开发服务，或更换端口；浏览器测试仍要求配置中的 5173 端口 |
| 页面打不开 | 确认开发服务仍在运行，并使用终端显示的实际地址 |
| 构建预览没有更新 | 先重新执行 `npm run build`，再刷新预览页面 |
| 浏览器测试连接失败 | 先启动 5173 端口的开发服务，测试配置不会自动启动服务器 |
| 浏览器测试找不到 Chrome | 安装 Chrome，或按测试章节切换到 Playwright 的 Chromium |
| 切换地址后找不到历史计划 | 使用原先的浏览器及同一主机、端口访问；记录保存在该站点的本地存储中 |
