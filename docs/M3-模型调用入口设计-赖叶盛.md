# M3 模型调用入口设计 · 赖叶盛（成员1）

> 范围：成员1 负责的「模型调用入口」= 后端侧统一调用大模型的客户端/服务。
> 前端经 `frontend/src/services/modelApi.ts`（8.4 四端点）调后端；本文件定义后端如何调用 LLM。
> 目标：provider 无关、配置驱动、超时/重试/错误映射到位，前端只收到「成功 JSON」或「中文报错」。

## 1. 总体链路

```
前端(store → 7阶段编排)
   │  POST /api/analyze | /api/plan | /api/plan/replan | /api/jobs/import
   ▼
后端路由(agent/backend)  ── 组装 prompt + 调 LLM ──►  大模型
   │  校验 JSON、映射成 8.4 响应结构                 (DeepSeek/通义/OpenAI 兼容)
   ▼
前端 modelApi.ts → ModelApiError(中文) 或 成功数据
```

- 密钥**只在后端**，前端永不接触（Q7 方向 + 安全要求）。
- 后端**无状态**（Q6）：每次 analyze/plan/replan 独立，前端用 localStorage 存草稿/方案/历史。

## 2. Provider 无关设计（关键决策）

采用 **OpenAI 兼容的 Chat Completions 协议**作为唯一接口形态：

- DeepSeek、通义千问（qwen）、OpenAI 均兼容该协议 → 切换厂商只改 3 个环境变量，代码零改。
- 配置项（走环境变量 / 部署平台 Secret，不进仓库）：
  - `LLM_BASE_URL`（如 `https://api.deepseek.com/v1`）
  - `LLM_API_KEY`
  - `LLM_MODEL`（如 `deepseek-chat` / `qwen-plus` / `gpt-4o-mini`）
- 选它而非各自 SDK：避免后端被某家 SDK 绑死，也便于本地用 Mock 联调。

## 3. 入口客户端契约（参考实现，Node ≥ 18 原生 fetch）

```ts
// agent/backend/src/llm/client.ts  —— 成员1 的「模型调用入口」核心
export type LlmRole = 'system' | 'user' | 'assistant'
export interface LlmMsg { role: LlmRole; content: string }

export class LlmClient {
  constructor(
    private baseUrl: string,   // process.env.LLM_BASE_URL
    private apiKey: string,    // process.env.LLM_API_KEY
    private model: string,     // process.env.LLM_MODEL
    private timeoutMs = 30_000,
    private maxRetries = 1,
  ) {}

  /** 调用一次对话；要求模型按 schema 回 JSON。失败抛 LlmError。 */
  async chat(messages: LlmMsg[], jsonMode = true): Promise<unknown> {
    for (let attempt = 0; attempt <= this.maxRetries; attempt++) {
      const ctrl = new AbortController()
      const timer = setTimeout(() => ctrl.abort(), this.timeoutMs)
      try {
        const res = await fetch(`${this.baseUrl}/chat/completions`, {
          method: 'POST',
          headers: {
            'Content-Type': 'application/json',
            Authorization: `Bearer ${this.apiKey}`,
          },
          body: JSON.stringify({
            model: this.model,
            messages,
            response_format: jsonMode ? { type: 'json_object' } : undefined,
            temperature: 0.3,
          }),
          signal: ctrl.signal,
        })
        clearTimeout(timer)
        if (res.status === 429) throw new LlmError('llm_rate_limit', '模型调用频繁，请稍后重试')
        if (res.status >= 500) throw new LlmError('llm_server', '模型服务异常，请稍后重试')
        if (!res.ok) throw new LlmError('llm_bad_request', '请求模型参数有误')
        const data = await res.json()
        return JSON.parse(data.choices[0].message.content)
      } catch (e) {
        clearTimeout(timer)
        if (e instanceof LlmError) throw e
        if (attempt < this.maxRetries) continue            // 超时/网络抖动重试 1 次
        throw new LlmError('llm_timeout', '模型响应超时，请稍后重试') // 兜底：直接报错（Q7，不降级）
      }
    }
    throw new LlmError('llm_unknown', '模型调用失败，请稍后重试')
  }
}

export class LlmError extends Error {
  code: string
  constructor(code: string, message: string) { super(message); this.name = 'LlmError'; this.code = code }
}
```

- **超时**：`AbortController` 30s；**重试**：仅对 5xx / 超时重试 1 次（避免对 4xx 无效重试）。
- **错误映射**：统一为 `code + 中文 message`，后端路由原样转成 `ModelApiError` 透传给前端（与 `modelApi.ts` 的 `code/message` 对齐）。
- **JSON 约束**：`response_format: json_object` + prompt 内给 schema，后端 `JSON.parse` 校验，失败抛 `llm_bad_response`。

## 4. 四个端点 ↔ 模型调用映射

| 8.4 端点 | Prompt 要点 | 模型返回 → 映射 |
|---|---|---|
| `/api/analyze` | 输入 jobs，要求输出技能统计 | `{ skills: SkillStat[] }`（Q1：技能规则由后端 prompt/知识持有，前端不带） |
| `/api/plan` | 输入 profile(含 scores/courses 软信号, Q5) + jobs + version(Q3 前端传入) | `{ plan: Plan }`，version 原样回写 |
| `/api/plan/replan` | 输入 before.plan + profile + jobs，要求给出变更 | `{ plan: Plan, changes: TaskChange[] }`（status ∈ 保留/推迟/新增/移除） |
| `/api/jobs/import` | 输入 url/text/role，要求解析成岗位 | `{ job: Job }`（source 置 imported，受 D1 约束） |
