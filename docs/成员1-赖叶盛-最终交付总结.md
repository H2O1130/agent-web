## 三、② 7 阶段串联（前端编排）

新增 `frontend/src/services/orchestrator.ts`，把 **画像 → 岗位样本 → 能力分析 → 方案生成 → 路线呈现 → 方案调整 → 历史留存** 串成一条链。

- 暴露 `analyzePhase / planPhase / replanPhase / importPhase` 四阶段函数。
- 用 `VITE_USE_MODEL` 一个开关统一切换「本地规则 / 后端接口」，**默认 `false` 走本地**，保证无后端也能完整运行、单测不挂。
- `store.generate` 改 `async` 走 `planPhase`；新增 `replan()` 走 `replanPhase` + `generating` 状态。
- `Wizard / Analysis / Adjust` 三视图改 `await`，按钮加「生成中…/调整中…」禁用态；**失败直接显示后端中文错误，不降级**（按 Q7）。
- `JobsPicker` 导入岗位在模型模式下走 `/api/jobs/import`，本地模式保持手填。

## 六、如何运行与切换模型模式

**前端（默认本地规则，无需后端）：**
```bash
cd frontend
npm install
npm run dev        # http://localhost:5173
```

**后端（可选，启用真实模型）：**
```bash
cd agent/backend
cp .env.example .env   # 填入 LLM_BASE_URL / LLM_API_KEY / LLM_MODEL
node src/server.js     # 默认 8787 端口，LLM_MOCK=1 可离线联调
```

**切换到大模型模式：**
- 后端 `.env` 填真实密钥，启动后端；
- 前端 `frontend/.env` 设 `VITE_USE_MODEL=true`；
- Vite 代理已把 `/api` 指向 `127.0.0.1:8787`。
