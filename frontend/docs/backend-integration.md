# 前端与现有后端对接

本次仅修改 `frontend/`，不修改后端逻辑。

## 对接范围与实施计划

- 对接现有 `GET /health`、`POST /api/llm/verify`、`POST /api/plan`。
- 开发与预览默认通过 `/backend` 代理访问 `http://127.0.0.1:8000`；`VITE_API_BASE` 可覆盖地址，显式留空时为本地演示。
- 保留现有画像、规划、调整、历史及导出流程；远程失败直接提示，不改用本地结果冒充成功。
- 模型配置支持浏览器覆盖密钥、模型名、模型服务地址，也允许使用后端环境配置；连接状态只反映实际验证结果。
- 校验规划响应后再保存，并隔离异步生成期间的输入变化与工作区重置。
- 岗位洞察与示例课程映射仍是本地预览。`skill_merger`、`course_mapping` 只有 Python API，没有 HTTP 路由，本次不虚构它们的接口。

实施顺序：接口与响应校验测试 → 最小请求实现/代理 → 模型设置与状态 → 生成流程及浏览器回归 → 实际后端契约验证。

## 本地启动

1. 在项目根目录进入 `backend/semester-planning/`，使用该模块依赖与环境启动：`python -m uvicorn app.main:app --host 127.0.0.1 --port 8000`。不要在旧的 `backend/` 目录启动同名入口，旧入口只有健康检查。
2. 在 `frontend/` 执行 `npm ci`（首次安装），然后 `npm run dev -- --port 5173 --strictPort`。
3. 页面打开「模型设置」。可使用后端已配置的密钥，或填入自己的密钥、模型名和服务地址。先测试连接，再保存应用。无密钥、错误模型或服务不可用时按后端返回显示错误。
4. 新建方案、岗位洞察页生成、调整条件都调用同一个 `/api/plan`，后端返回学期、寒暑假、微任务与原因；历史版本、完成标记、差异计算及 Markdown 导出仍由前端处理。

`VITE_API_BASE` 未设置时默认为 `/backend`；设置为 `http://127.0.0.1:8000` 可直接请求后端。使用其他前端来源时需注意现有后端仅允许5173的本机来源，开发时优先使用同源代理。生产环境需要由部署服务器转发 `/backend` 到后端，或设置后端允许的前端来源及地址；Vite代理只对开发/预览有效。

## 验证记录

- `npm test`：58项通过；`npm run typecheck`、`npm run build` 通过。
- 浏览器：本地演示10项通过（含六档宽度、导出与历史），远程契约9项通过（请求、错误、模型设置与异步状态）。
- 实际未修改的后端 + 本地受控模型响应：浏览器经 Vite 代理完成健康检查、模型验证、生成14个微任务（含2个学期、2个假期）、12→0小时重规划及旧版本保护；页面无运行异常。该验证不等于真实付费模型质量评测。
- 独立代码审查未发现阻断问题；后端78个文件的整体哈希与修改前一致。

浏览器回归分两种模式运行：`tests/app.spec.ts` 使用显式空 `VITE_API_BASE` 的本地演示服务；`tests/backend-integration.spec.ts` 使用默认后端模式，通过 `PATHPILOT_E2E_BASE_URL` 指定服务地址。后者拦截接口返回契约夹具，和上一项实际后端联调属于不同验证层次。
